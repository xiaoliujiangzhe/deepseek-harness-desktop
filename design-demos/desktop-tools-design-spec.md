# DSH Desktop 工具界面三方向设计规格

本轮设计对象不是一个独立网站，而是 DeepSeek Harness 社区桌面壳新增的两项桌面能力：内置浏览器和插件中心。用户主要在 Windows 桌面端使用它，既可能是熟悉 Harness profile、Cordis 和终端的开发者，也可能只想双击应用、在对话旁查看网页并按按钮安装插件的普通用户。界面必须先维持 DeepSeek Harness 原有对话体验的主导地位，再让浏览器和插件管理成为容易发现、随时退出、不会误操作的桌面工具；不能把整个产品改造成营销网站，也不能让工具栏挤占对话所需空间。

三个方向统一以 1440×900 桌面窗口绘制，统一使用官方鲸鱼 SVG、DeepSeek Blue `#4D6BFE`、中性白灰表面和 Windows 友好的 Segoe UI 字体体系。方向稿中的产品事实只使用本地可验证内容：当前 Harness 版本为 `0.1.1-rc.2`；当前 `.dsh/profiles/web/package.json` 中第三方依赖数量为 0；社区仓库索引入口为 GitHub Topic `dsh-plugin`；插件安装默认禁用第三方安装脚本并要求重启验证。不能虚构插件名称、星标数、下载量、评分、作者评价或兼容性结论。仓库索引未加载时应显示诚实空状态，已安装区可显示“0 个第三方插件”。浏览器方向稿使用用户已给出的 DeepSeek Vision 文档 URL，但不虚构文档正文。

浏览器必须具备用户自然预期的后退、前进、刷新、地址输入、打开和关闭控制，动态标题和长网址不能挤坏工具栏。插件中心必须具备仓库搜索、仓库/已安装两个视图、兼容性提示、安装/卸载入口、操作中状态、失败详情和重启提示。危险操作不能只依赖颜色表达；卸载需要清楚的文字命令，安装来源不明确或兼容范围无法核实时应显示“待核实”而不是猜测。所有按钮点击区域至少 36px，核心命令优先达到 40px；正文不小于 14px，辅助标签不小于 12px。

三种布局骨架必须实质不同。方向 A 把“浏览器”和“插件中心”加入左侧主导航，使用单一全宽工作区，适合希望界面稳定、学习成本低的用户。方向 B 在窗口顶部建立工作区标签，允许多个网页标签和一个插件中心标签，适合频繁在多个上下文之间切换的用户。方向 C 保留左侧对话并在右侧打开浏览器分屏，插件中心作为可替换的右侧工具面板，最接近研究资料与对话同时可见的工作方式。用户选择方向后才将对应导航、浏览器 chrome 和插件中心控件注入正式 `preload-main.js`；本轮 HTML 只用于确认视觉与交互骨架。
